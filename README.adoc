= Install Coordinator

D daemon with **two surfaces**: a local lay-user app window and an admin remote-control HTTP API.

## Why

Windows blocks parallel MSI sessions via `_MSIExecute`. GUI users double-click installers and get error 1618. Install Coordinator collects jobs, explains waits, and runs MSI steps one at a time while allowing disjoint work in parallel when claims permit.

## Surfaces

* **User (local)** — `install-coordinator gui` opens a framed app window at `/ui/user`. Plain language, no admin jargon. Localhost only.
* **Admin (remote-capable)** — JSON API + `/ui/admin` for operators. Bind beyond loopback with `--remote --auth-token=…`; remote clients send `Authorization: Bearer <token>`.

## Commands

```powershell
install-coordinator daemon          # localhost HTTP on :17420
install-coordinator daemon --remote --auth-token=SECRET   # LAN/admin remote control
install-coordinator submit app.json # thin stub (default)
install-coordinator gui             # local user app window
install-coordinator list active
install-coordinator session --lock-elevation --batch-terms --scope=perMachine
install-coordinator shortcut <id> --desktop
```

Environment: `INSTALL_COORD_BIND`, `INSTALL_COORD_AUTH_TOKEN`, `INSTALL_COORD_REMOTE=1`, `INSTALL_COORD_HTTP_PORT`.

## Manifest (minimal)

```json
{
  "displayName": "My App",
  "presentation": "thinStub",
  "termsAccepted": true,
  "scope": "perUser",
  "claims": { "msi": true },
  "steps": [
    { "kind": "msiexec", "path": "C:/setup.msi", "args": ["/passive"] }
  ]
}
```

## Build

```powershell
dub build --config=application
```
